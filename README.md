# relateBot
This Discord bot correlates Discord Server Members with external Registration database by 
 * Creating unique invite
 * Saving invite in registration database
 * Relating used invite with user email in registration database 
 * Synchronizing member data to registration database
 * Keep synchronizing changes and members' role selection
 
## How to Set up 
 
### Create your own application 
at https://discord.com/developers/applications 
For more info, please visit https://discordpy.readthedocs.io/en/stable/discord.html 
 
### Install Node and packages
```
➜  relateBot git:(main) node -v
v18.9.0
➜  relateBot git:(main) npm -v
8.19.1
➜  relateBot git:(main) npm i
```

### Prepare Config File
Generate `config_prod.json` file. `config.json` will help guide you. 

#### Key configuration notes
- Copy `configs/service/config.json` to `configs/service/config_prod.json` (or `config_dev.json`) and replace placeholder values with actual values.
- Important fields you must set:
	- `token` — your Discord bot token (Bot -> Token in Discord Developer Portal).
	- `clientId` — Discord Application client id (used for command deployment).
	- `guildId` — the target Discord server id to constrain development/testing commands.
	- `partnerConfig.notion.request.headers.Authorization` — set to `Bearer <NOTION_INTERNAL_INTEGRATION_SECRET>`.
	- `partnerConfig.google.credentials.tokens.refresh_token` — place a refresh token generated by the helper script in `poc/gmail/generateTokenWithOneTimeUseGoogleCode.js`.
	- `registrations.email` — array of possible email field names to look for in incoming registration payloads.

Keep secrets out of source control; prefer using environment secrets or deployment tooling to inject them.

### Deploy the commands
```
➜  relateBot git:(main) npm run deploy
```

This runs `deploy-commands.js` and registers your slash commands with Discord for the configured `clientId` and `guildId`.

### Run Your Bot
```
➜  relateBot git:(main) npm run prod
```

### For pm2 users
Update config file to point correct npm path
```
➜  relateBot git:(main) pm2 start configs/pm2/prod.yml
```

### Scripts
- `npm run start` — start the bot with `NODE_ENV` unset (default behavior)
- `npm run dev` — start with `NODE_ENV=dev` (development behaviour/config)
- `npm run prod` — start with `NODE_ENV=prod` (production behaviour/config)
- `npm run nyp` — start with `NODE_ENV=nyp` (custom environment)
- `npm run deploy` — deploy/refresh Discord application commands for the configured environment

## Integrations

### Discord
- Create an application in the Discord Developer Portal, add a Bot user, and copy the bot token into the configuration `token`.
- When inviting the bot to a server, request `applications.commands` and the `bot` scope and give it appropriate permissions (Manage Roles, Send Messages, Manage Messages as required).
- If you use user/member data (role syncing, queries for members), enable the Privileged Gateway Intents (SERVER MEMBERS INTENT) for your bot in the Developer Portal.

### Notion
- Create an internal integration in Notion and copy the internal integration secret into `partnerConfig.notion.request.headers.Authorization` as `Bearer <secret>`.
- Share the target databases with the integration so it has access to read and modify pages.

### Google / Email
- Generate OAuth credentials and a refresh token if you want to use the email templates or send messages via Gmail API. Use the helper `poc/gmail/generateTokenWithOneTimeUseGoogleCode.js` to obtain a refresh token interactively and store it in `partnerConfig.google.credentials.tokens.refresh_token`.

## Configuration reference (quick)
- `configs/service/config.json` contains all keys used by the bot. Look at `partnerConfig.notion.keymappings` and `partnerConfig.notion.keyTypes` to adapt the mapping between Notion and bot data models.

## Commands & Features
- Public commands are defined in `configs/service/config.json` under `publicCommands` (examples: `myprofile`, `skills`, `references`).
- Private/admin commands are available to roles listed under `allowedRoles` and defined in `privateCommands` (examples: `invite`, `correlate`, `assign mentor`).

## Development & Contributing
- Add new integrations by implementing a client in `lib/clients/` and registering it via `lib/clients/index.js`.
- Run locally with `npm run dev` and use a test guild for development to avoid modifying production servers.
- Opening issues and PRs with clear descriptions and reproduction steps is appreciated.

## Data & Templates
- Email templates are stored under `data/templates/` and referenced by `configs/service/config.json`.
